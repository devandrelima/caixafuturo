# Protocolo de evidências reais

Por task: ID, commit verificável, diff, testes locais e saída, falhas e correções, contexto seletivo e SHA-256 da CLI (estimativa de tokens não é consumo faturado). Por sprint: regressão afetada, build, E2E, cobertura do código novo/alterado >=80% medida, demonstração reproduzível, revisão UI e feedback humano. Checkpoint de alto risco e S03/S06: suíte completa e cobertura global >=80%. Os resultados de CLI são validação estrutural, não execução do aplicativo. Não inventar economia de tokens ou tempo e não reduzir cobertura artificialmente.
